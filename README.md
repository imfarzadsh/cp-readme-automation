# 📊 cp-readme-automation

A GitHub Action that automatically keeps the `README.md` files of your **competitive programming / problem-solving repository** up to date with solved-problem statistics, navigation tables and links.

Push a new solution → the action runs → every README in your repo refreshes itself.

## ✨ What it does

For **every** `README.md` in the repository, the action counts the code files in that folder and all of its sub-folders, then writes a stats block into it. The layout depends on where the README lives:

| README location | What you get | Example |
| --- | --- | --- |
| Root | Total solved + per-extension breakdown, table of top-level folders (**Platforms**), last 5 pushed solutions | this page |
| Folder with sub-folders | Total solved + per-extension breakdown, table of sub-folders (**Category**) | [`LeetCode/`](LeetCode/) |
| Folder without sub-folders | Total solved + per-extension breakdown, numbered problem list (**Number / Problem**) | [`LeetCode/Easy/`](LeetCode/Easy/) |

## 🚀 Quick start

### Option 1: reusable workflow (recommended)

You don't need to copy any script. Create **one** file in your repository:

`.github/workflows/readme-stats.yml`

```yaml
name: Update README stats

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: write

jobs:
  stats:
    uses: imfarzadsh/cp-readme-automation/.github/workflows/readme-stats.yml@main
```

Then:

1. Go to **Settings → Actions → General → Workflow permissions** and select **Read and write permissions**.
2. Push to `main` (or run the workflow manually from the **Actions** tab).

When this repository improves, your repositories get the new version automatically.

### Option 2: use as a template / fork

Click **Use this template** (or fork the repo) to get the workflow and the script in your own repository. Then:

1. Delete the sample folders (`Codeforces`, `LeetCode`, `AtCoder`) and replace this README with your own.
2. If you want to customize the script, open `.github/workflows/readme-stats.yml` in your copy and replace `imfarzadsh/cp-readme-automation` with **your own** `username/repository`, so the workflow uses your modified script.

By default the stats block is appended to the **end** of each README. To control the position, put these two HTML comments in the README where you want the block. Everything between them is replaced on each run, and everything outside them is left untouched:

Write your own text **outside** these two lines.

## 📁 Expected repository structure

```text
.
├── README.md                      ← root: platforms + last 5 solutions
├── Codeforces/
│   ├── README.md                  ← no sub-folders: numbered problem list
│   ├── 0001-4-Watermelon.cpp
│   └── 0002-71-Way-Too-Long-Words.py
└── LeetCode/
    ├── README.md                  ← has sub-folders: category table
    ├── Easy/
    │   ├── README.md
    │   └── 0001-1-Two-Sum.cpp
    └── Hard/
        ├── README.md
        └── 0001-4-Median-of-Two-Sorted-Arrays.py
```

### File naming convention

```text
[Index]-[ProblemID]-[ProblemName].[ext]
0001-1-Two-Sum.cpp
```

Only `ProblemName` is shown in the **Problem** column. If a file name doesn't follow this pattern, the whole file name (without extension) is used.

## ⚙️ Configuration

All settings are at the top of `.github/scripts/update_readme_stats.py`:

| Setting | Default | Description |
| --- | --- | --- |
| `CODE_EXTS` | `.cpp .c .py .java .js .go .rs …` | File extensions counted as solved problems |
| `RECENT_LIMIT` | `5` | Number of recent solutions shown in the root README |

Other things you may want to change:

- **Branch:** edit `branches: [main]` in the workflow if your default branch has another name.
- **Hidden folders** (names starting with `.`, such as `.github`) and `README.md` files are never counted.

---

## 🔧 How it works

1. The workflow checks out your repository with its full history.
2. The script reads the list of git-tracked files (so `.gitignore`d files are skipped automatically).
3. For each `README.md`, it builds the right layout and writes it into the README.
4. If anything changed, the action commits with `chore: update README stats [skip ci]` and pushes.

## 🩺 Troubleshooting

**`Not Found` error when checking out the tool**
The repository holding the script must be **public**, or you must provide a token that can read it.

**`403` error when pushing**
Enable **Settings → Actions → General → Workflow permissions → Read and write permissions**.

**Merge conflict markers (`<<<<<<< HEAD`) in a README**
The action creates a commit after every push, so your local copy falls behind. Before pushing, run:

```bash
git pull --rebase
git push
```

To make this the default behavior:

```bash
git config --global pull.rebase true
```

**The workflow doesn't run**
Make sure the file is at `.github/workflows/readme-stats.yml`, the branch name matches, and Actions are enabled for the repository.
